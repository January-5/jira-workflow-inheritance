# 原生草稿发布验收清单

适用：Jira DC 9.12.11，Jira JVM 和插件目标均为 Java 17。当前仅完成本地测试；以下需在非生产 Jira 实例执行并记录结果。

## 正常路径

1. 安装开发插件，确认 OSGi 组件和数值字段搜索器成功启用。使用 Jira 管理员访问管理页。
2. 准备父流程 A→B→C，配置 A=0、B=60、C=100。创建子流程，在 Jira 编辑器中插入 X，指定 X 属于 A。
3. 创建测试 Issue 并流转到 B；确认保存的进度为 60，JQL、列表和导出均可读到该数值。
4. 在活动父流程建立原生草稿。插件中把 B 配置为 70，保存进度草稿，点击“校验发布”。确认展示的目标状态正确。
5. 点击“发布已校验草稿”。核对原生草稿消失、发布记录为 APPLIED、生效规则为 70；原有 B 状态 Issue 仍为 60。
6. 核对无冲突子流程同步规则；有管理员草稿的子流程保留旧规则并显示待处理。仅 Jira 作者/更新时间变化不得制造结构冲突。
7. 将原 Issue 正常流转到下一状态，核对按最新适用规则写入进度，不自动补走新增节点。

## 拒绝与恢复

| 场景 | 应有结果 |
|---|---|
| 非 Jira 管理员请求预览、发布、恢复或关闭记录 | 服务端拒绝 |
| 预览后修改草稿、进度配置或父版本 | 拒绝过期发布，不执行原生发布 |
| 删除父节点、子流程删除继承节点或新增绕过必经节点的路径 | 插件发布前拒绝 |
| 原生要求迁移或不允许发布 | 展示原生校验错误，不绕过、不自建迁移规则 |
| 原生发布成功，规则保存失败 | 留下 PENDING，旧规则仍在；匹配版本恢复后生效，不重复原生发布 |
| 发布失败且正式版本未变化 | 可以关闭失败记录，保留原生草稿；修复后重新校验发布 |
| 失败后配置或工作流又发生变化 | 拒绝按旧记录恢复；先人工处理流程与规则，再校验并关闭记录 |
| 恢复重复提交或旧记录 ID | 已完成记录不重复发布；过期 ID 被拒绝 |

## 当前边界

- 此入口仅保护通过插件管理页发起的发布，不表示已拦截 Jira 自带发布页、导入或第三方发布。
- 父新增 D 的子结构合并目前提供预览，尚未自动发布子流程。此项必须作为未完成项保留，不能按自动同步已验收处理。
- 原生发布与进度规则生效不属于一个已验证的原子事务。须测试这段窗口内 Issue 流转、插件重启、数据库失败和 DC 双节点竞争；不能以本地代理测试替代。
- 发布不迁移 Issue、不回填已有百分比，不执行批量业务流转。导入、迁移及创建初始化另行验收。
