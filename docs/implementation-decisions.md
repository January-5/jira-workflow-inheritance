# 原生规则优先与补充实现规则

日期：2026-09-28。依据：用户确认“如果 Jira 原生工作流已有规则就按照原有的方案，如果没有的先按照建议的实现”。

本文记录实施决策，不表示所有条目已开发或通过 Jira 实例验收。实现进度另见 implementation-status.md。原生规则以目标版本 Jira DC 9.12.11 为准，不能用较新版本文档替代版本验证。

## 优先级

1. Jira 原生状态、工作流、草稿、方案、权限、流转校验、系统后置操作、状态迁移及引用删除规则照常执行。
2. 本插件额外施加已确认的继承及进度约束。原生允许删除状态，并不取消本需求对父状态及继承状态的保护。
3. Jira 原生没有父子工作流持续继承、进度累计百分比及父配置追加策略；这些部分使用下表补充规则。
4. 不能安全表达的合并进入待处理，保留原已发布版本和已有草稿；不得以覆盖、删除本地配置或猜测映射代替解决冲突。

## 补充规则

| 编号 | 采用规则 | 边界 |
|---|---|---|
| Q-01 | 同一父阶段允许扩展分支、回退、循环；将子流程中不经过其他父节点的路径折叠后，父节点间的关系必须与父流程许可一致 | 保留每条父路径能力，禁止新增未经许可的父节点间路径；流转身份、条件和全局流转仍按原生机制处理 |
| Q-02 | 扩展状态明确指定一个父阶段，多入口不按最近访问节点推断 | 线性插入 D 后 X 改属 D 的既定规则不变；复杂自动归属不明确时待处理 |
| Q-03 | 扩展状态删除、占用检查、状态映射和迁移采用 Jira 原生适用方案，不另设“被 Issue 占用就一律禁止删除”的规则 | 插件额外校验父/继承节点不可删除和路径约束；原生不允许的操作不能绕过。迁移保留已保存进度，后续成功状态流转再更新 |
| Q-04 | 复用原生工作流编辑器，六类非结构配置允许编辑 | 未指定第三方插件，不承诺其兼容认证；未知配置不得静默丢弃 |
| Q-05 | 普通新建 Issue 按初始状态已发布规则初始化；导入、迁移和首次启用不主动回填 | 需可靠区分创建来源，不能把所有创建事件都视为普通新建；无法区分时不能猜测。已有值在下次成功状态流转时更新 |
| Q-06 | 0–100，最多两位有效小数，超出精度拒绝保存，不舍入 | 60.250 与 60.25 数值等价；展示带 %，查询数值为 60.25，不按 0.6025 查询 |
| Q-07 | 本期通过父流程创建新子流程 | 不提供已有流程绑定、换父流程、解除继承 |
| Q-08 | 子流程已有管理员草稿时转待处理 | 不覆盖、不自动合并、不顺带发布；处理后重试 |
| Q-09 | 目标是保护所有支持入口的父节点和路径约束 | 必须分别验证原生编辑器、导入、REST、第三方入口、全局 Statuses。未验证入口明确列为限制；事后事件不是可取消的发布前校验 |
| Q-10 | 万条工作流、百万 Issue 作为容量测试目标 | 无业务给定的子流程分布、峰值和时限，先测量报告；不得虚构性能达标结论 |
| Q-11 | 节点负责人、默认指派、SLA 不新增专有功能 | 继续使用原生或现有插件能力 |
| Q-13 | 无原生草稿发布过程的未激活父模板，增加“确认生效并同步”边界 | 编辑中间态不自动传播；已激活工作流仍遵循原生草稿发布 |

## Q-12 配置追加规则

| 情形 | 处理 |
|---|---|
| 子未拆分 A→B | 对应子 A→B 为追加目标 |
| A→X→B 或 A→X1→X2→B | 唯一替代路径的最后一段为目标，即 X→B 或 X2→B |
| 多替代路径、平行同端点流转、映射不唯一 | 待处理，管理员明确目标后再次校验 |
| 流转界面 | 相同不重复；子未配置时可使用父新增值；已有不同界面待处理，不覆盖 |
| 属性 | 新键追加；同键同值不重复；同键不同值待处理 |
| 条件 | 保留父子原条件组，新增条件组按 AND 组合；无法无损组合时待处理 |
| 校验器 | 新增项追加到现有项之后，完全相同项不重复 |
| 后置操作 | 遵守 Jira 系统必需操作及顺序；不得重复系统操作；执行位置不能可靠确定时待处理 |
| 父修改已有配置、父删除配置 | 待处理，保留子配置；不同时默认执行新旧动作，也不自动删除子配置 |
| 触发器与未知第三方配置 | 能证明完全相同则不重复；原生不允许追加或无法证明可安全追加时待处理 |
| 批次重试 | 同一父版本、子流程及目标配置仅成功追加一次，恢复不得重复配置或执行业务流转 |

追加计划必须先整体校验，出现冲突不能发布仅完成一部分的子流程。原业务动作所在段和执行时机由管理员管理，不增加业务时机限制。

## 原生接口依据与验证记录

已检查本地官方 Jira 9.12.11 jira-api JAR 的公开签名：WorkflowService 提供草稿创建、复制、更新、validateOverwriteWorkflow、overwriteActiveWorkflow；WorkflowManager 提供工作流与草稿读取；DraftWorkflowPublishedEvent 提供发布后工作流及原工作流。

这些签名证明相关接口存在，不证明发布事件可取消、不证明能拦截所有原生入口，也不证明调用具备跨插件事务原子性。

删除扩展状态时，不能据此推断所有活动工作流草稿均支持直接移除占用状态；具体是否需要复制工作流、方案变更及原生迁移向导，以目标版本实际支持的操作为准。插件不自行实现状态迁移引擎。

- [Jira 9.12.11 WorkflowManager API](https://docs.atlassian.com/software/jira/docs/api/9.12.11/com/atlassian/jira/workflow/WorkflowManager.html)
