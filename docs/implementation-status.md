## 依据及范围

依据父目录中的《Jira-DC工作流继承与进度管理需求文档》《Jira-DC功能拆分与实施计划》《Jira-DC需求稳定性与基线确认》及《Jira DC 工作流继承与进度管理插件开发方案计划书V1.0》。原始文档保留原位。

本批交付为独立于 Jira API 的领域规则及单元测试，是业务实现的第一步，不代表对应模块已完成或可在 Jira 界面操作。

## 已实现

| 模块范围 | 代码 | 本批能力 |
|---|---|---|
| 继承关系管理 | `InheritanceRules` | 允许一个父流程对应多个子流程；拒绝自继承、重复绑定、多级继承及已有非法关系；拒绝删除被项目、方案或子流程引用的工作流 |
| 进度配置 | `PublishedProgressRules` | 每个父状态必须配置 0–100 的累计百分比；扩展状态显式归属父阶段，不参与独立分配；校验配置完整性并生成不可变快照 |
| 流转进度计算 | `TransitionProgress` | 成功流转时按目标状态和本次适用的已发布快照计算；失败保留原值；记录工作流、状态和规则版本供后续持久化使用 |

不要求各节点进度之和为 100，不自动平均分配，不额外强制起点为 0、终点为 100 或进度单调递增。百分比内部使用 BigDecimal；界面输入精度和展示舍入规则仍待确定。

示例：A=0、B=60、X 归属 A，进入 B 得到 60，进入 X 得到 0，包括合法的 B→X 回退。新配置发布不会修改已有计算结果；同步待处理的子流程应继续传入自身旧的已发布快照。X 改归属新增节点 D 后，仅后续流转进入 X 时按新快照计算。

## 后续实现顺序与边界

1. 核实 Jira 9.12.11 官方 API，接入存储、管理员权限、继承关系和配置管理。关系校验与写入需在同一集群安全事务中完成，项目和方案引用需由 Jira 实际查询，不能仅依赖调用方输入。
2. 实现节点、路径约束及子流程编辑。继承内容中只锁定节点和路径约束，条件、校验器、界面、后置操作、触发器、属性允许人工修改。
3. 实现父流程发布后的同步任务、冲突检查、自动发布、待处理和重试。子流程同步成功后才能切换适用的进度规则快照。
4. 实现父流转配置向子路径末段追加。A→B 拆为 A→X→B 时原配置由人工管理，父流程更新追加到 X→B，同一批次重试不得重复追加。单值配置冲突、条件组合、后置操作顺序及复杂路径映射等未定细则需按需求待确认项处理，不自行推断。
5. 接入 Issue 成功状态流转和百分比持久化、展示、JQL、列表及导出。发布、同步、浏览和重建索引不能触发已有 Issue 进度重算。失败补偿必须使用对应流转版本，并防止旧任务覆盖后续流转；当前计算结果尚不包含实现这一点所需的 Issue 流转序号和事务机制。
6. 完成 Jira 实例集成验证、DC 并发与故障恢复测试以及规模性能验证。

本批未实现自动发布、配置追加、Issue 更新或数据库持久化；不得据此宣称这些功能已可用。
