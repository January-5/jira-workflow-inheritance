## 本批重点

- 管理页可显式发布 Jira 已有草稿：先执行原生校验及插件约束，再调用 `WorkflowService.overwriteActiveWorkflow`，最后切换规则。该入口不覆盖管理员草稿内容，不提供状态迁移替代方案。
- 发布尝试先独立持久化为 PREPARED，再跨越原生发布边界。失败保留 PENDING；恢复要求当前描述符、配置版本及父版本仍匹配，并且无新草稿，不再次调用发布接口。
- 未实际发布的失败记录可在确认原正式版本未变化后关闭；管理员已另外完成流程和规则处理的记录，可在校验二者一致后关闭为 RESOLVED。
- 内容比较仅排除 Jira 发布作者、作者 key 和更新时间三项根元数据；业务属性、节点和路径仍参与比较，避免正常发布产生错误的子流程结构冲突。

- 统一编译目标 Java 17，使用 Jira 对应的 Spring Beans 5.3.33 provided 依赖。
- 修复 `DelegatingJiraIssueEvent` 解包。普通 `IssueEvent` 与 `JiraIssueEvent` 不是同一接口层次，不能直接相互强转。
- 恢复任务在字段写入前和索引前分别检查当前工作流、状态和后续历史，避免旧任务生成过期索引。
- `WorkflowAppendPlanner` 可预览 A→X→Y→B 在父插入 D 后变为 A→D→X→Y→B。重新分配新增步骤/流转 ID，保留子配置，X/Y 阶段由 A 调整为 D。
- 新增属性、界面、校验器及安全条件组合追加到 Y→B。改变后置操作、触发器、节点属性等未覆盖配置会报冲突，不静默丢弃。
- 合并使用独立描述符副本；预览不创建草稿、不发布、不改变 Issue 或有效配置版本。

## 保持的业务规则

进度为人工配置的累计值，不自动平均分配、不要求总和 100、不额外强制单调递增。扩展状态显式归属父阶段。发布、同步、读取、导出和重建索引不得重算已有 Issue；后续成功状态流转按适用的已发布快照更新。

扩展状态删除、占用和迁移采用 Jira 原生适用方案。插件不另建迁移引擎；父/继承节点不可删除的约束仍需在所有支持入口落实。
